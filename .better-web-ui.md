## Design Context

### Users
ETHGlobal Mumbai judges and the person giving a two-minute demo. They need to see a frame transaction the public mempool refuses and the alt mempool admits, plus an honest Anon-RPC read path. Secondary audience is a developer reading the repo after the hackathon.

### Brand Personality
Calm, specific, slightly dry. Three words: warm, strict, honest. The interface should feel like an ops tool a person trusts with a key, not a campaign site.

### Aesthetic Direction
PostHog product and posthog.com density: olive-grey page, white panels, chunky heat-orange primary action, a separate red for danger, medium-density sidebar and tables. Light mode only for the demo. Do not copy the PostHog logo, hedgehog, RoundHog, or Squeak. Do not ship a font CDN or a tracker. System UI sans. Radii stay small (8px panels, 6px controls).

### Implementation Defaults
Detected stack, not a framework fallback: Vite + React 19, one global token file (`apps/web/src/tokens.css`), no component library, no Tailwind, no shadcn, no Radix or Base UI. Forms are plain controls. Tables are semantic `<table>` elements. No virtualization. Chain code lives in `packages/core`. The console is one component with tab state, not a router.

### Design Principles
- Match PostHog’s page structure (nav, hero with a real product surface, tabbed demo, product index, numbered story, closing CTA), using Shepherd’s own words and mark.
- One orange primary action per screen. Danger stays `#db3707`, never the brand orange.
- The ops log shows method, route, and verdict. It does not show addresses, payloads, or keys.
- Say what Anon-RPC does not do. The worker sees request bodies. The reference worker does not unlink IP.
- Prefer a screenshot or a live console panel over a sentence that describes the same thing.
